## 2. FJSP 的现实应用场景

- FJSP：Flexible Job Shop Scheduling Problem，柔性作业车间调度问题。
- 基本含义：
  - 一个作业包含多道工序。
  - 每道工序可以由多台候选机器加工。
  - 调度系统需要同时决定“先加工哪道工序”和“分配到哪台机器”。
- 典型场景，简单带过即可：
  - 机械加工与金属加工车间：铣削、钻孔、磨削等工序可由不同设备完成。
  - 半导体芯片制造：工艺路线长，设备昂贵，队列和设备可用性影响显著。
  - 汽车零部件生产线：零件批次、工艺路线和设备能力差异明显。
  - 企业内小批量、多品种生产：订单变化快，固定流水线难以适应。
- 过渡句：
  - “这些场景说明 FJSP 本身具有实际意义，但真实车间中还存在一个传统调度容易忽略的问题：设备健康状态。”
- 时间：1 分钟

## 3. 为什么引入 RUL

- 传统 FJSP 主要考虑工序顺序、机器分配、加工时间、交期和拖期。
- 真实车间中的机器并非稳定不变：
  - 设备会随加工持续退化。
  - 健康下降会提高故障风险。
  - 维护会占用机器时间，并改变后续机器可用性。
- RUL：Remaining Useful Life，剩余使用寿命。
  - 含义：设备从当前状态继续运行到失效或需要维护之前，还能安全运行的寿命余量。
- 引入 RUL 的意义：
  - 从被动维修或固定周期维修转向预测性维护。
  - 避免维护太早造成寿命浪费，也避免维护太晚导致故障和拖期。
  - 让调度系统不仅知道机器是否空闲，还知道机器是否健康、是否适合继续加工。
- 时间：1 分钟

## 9. 总体系统设计

- 系统由三层组成：
  - 健康估计层：GRU 根据退化序列输出归一化 RUL/健康状态。
  - 维护决策层：根据健康状态和生产压力选择 DN、IM、CM。
  - 调度决策层：根据作业、机器、交期和健康状态选择派工规则。
- 闭环关系：
  - 调度动作决定机器加工负荷，从而影响退化过程。
  - 维护动作占用机器时间，并改变后续可用性。
  - RUL 预测持续为维护和调度提供健康信息。
- 代码对应：
  - `src/env.py`：事件驱动车间环境。
  - `src/degradation.py`：退化轨迹回放。
  - `src/rul_predictor.py`：GRU RUL 预测器。
  - `src/agents.py`：DDQN、分层 DDQN、THDQN、PPO。
  - `src/pomcp.py`：POMCP 在线规划器。
- 建议图示：RUL 预测 -> 维护智能体/调度智能体 -> 事件驱动车间 -> 新状态。
- 时间：1 分钟

## 10. RUL 预测方法

- 输入特征：单变量 `Differential_pressure`。
- 时间窗口：`RUL_WINDOW = 30`。
- 模型结构：
  - GRU 提取退化序列的时间依赖特征。
  - Dropout 降低过拟合。
  - MLP Head 输出标量。
  - Sigmoid 将输出限制在 0 到 1，作为归一化 RUL。
- 训练设置：
  - Data_No = 18。
  - 按 `Time` 升序排列。
  - 80% 训练，20% 验证。
  - hidden_dim = 40，num_layers = 1，dropout = 0.25。
  - lr = 1e-3，batch_size = 1024，epochs = 250。
- 在线使用：
  - 对各机器退化轨迹生成健康缓存。
  - 对缓存结果做单调修正，避免回归噪声导致局部“健康回升”。
- 时间：1 分钟

## 11. 调度与维护方法

- 调度端：
  - 参考 Luo 2021 的 rule-based action 思路，不直接输出工序-机器对，而是选择 6 条派工规则。
  - THDQN：高层选择调度目标，低层在目标条件下选择规则。
  - PPO：作为扁平策略优化对照，直接学习状态到 6 条规则概率分布。
- 6 条规则：
  - EDD + Earliest Idle Machine。
  - EDD + Shortest Processing Time Machine。
  - 最大加权拖期风险 + SPT Machine。
  - SRPT + SPT Machine。
  - LRPT + Earliest Idle Machine。
  - Minimum Slack + Earliest Idle Machine。
- 维护端：
  - 动作空间：DN、IM、CM。
  - flat DDQN：单层结构，直接选择 DN/IM/CM。
  - hier DDQN：先判断是否维护，再判断 IM 或 CM。
  - POMCP：用粒子信念和蒙特卡洛树搜索进行在线规划。
- 时间：1.5 分钟

## 12. 实验设计与创新点

- 动态场景设计：
  - λ 表示作业到达间隔均值，λ 越小，作业到达越密集，负载越高。
  - λ = 20、40、60。
  - DDT 表示交期紧度，DDT 越小，交期越紧。
  - DDT = 1.0、1.5、2.0。
  - 使用 `grid_full` 覆盖不同负载和交期压力组合。
- 配对实验设计：
  - 调度器：THDQN、PPO。
  - 维护器：flat_ddqn、hier_ddqn、pomcp。
  - 共 6 组组合。
- 本文创新/改造点：
  - 将 RUL 预测、维护决策、调度决策放入同一事件驱动闭环。
  - 引入动态 λ/DDT 场景，而不是只使用固定环境。
  - 维护端设计分层 DDQN，把“是否维护”和“维护类型”拆开。
  - 通过多组配对实验分析调度结构与维护结构的匹配关系。
- 时间：1 分钟

## 14. 结果机制与核心结论

- THDQN + hier_ddqn 表现最好的原因：
  - THDQN 高层根据场景压力切换目标，低层选择规则。
  - hier DDQN 维护端先判断“是否需要维护”，再判断“维护强度”。
  - 两个层级结构形成匹配，使调度目标切换能得到维护端支撑。
- THDQN + flat_ddqn 表现较差的原因：
  - flat DDQN 把 DN、IM、CM 放在同一层价值函数中比较。
  - 在复杂动态压力下，维护时机和维护类型容易混在一起。
  - 层级调度如果缺少稳定维护响应，反而可能放大结构不匹配。
- 核心结论：
  - 本文结果不能简单概括为“某个调度器最好”或“某个维护器最好”。
  - 更准确的结论是：调度结构与维护结构的匹配关系决定系统表现。

### Q1：你的工作和 Luo 2021 的区别是什么？

- Luo 2021 主要提供动态 FJSP 中 THDQN 和 rule-based 调度思路。
- 本文在此基础上加入设备退化、RUL 健康状态和维护动作影响。
- 本文还引入动态 λ/DDT 场景，并将 THDQN 与 PPO、flat/hier/POMCP 维护器进行配对比较。

### Q2：你的工作和 Ding 2025 的区别是什么？

- Ding 2025 提供 RUL-GRU 和生产维护协同方向的参考。
- 本文使用其启发的 GRU-RUL 思路，但在自己的事件驱动车间环境中实现。
- 本文重点不是只复现 RUL 预测或多智能体框架，而是分析调度器与维护器结构之间的匹配关系。

### Q3：为什么要用动态 λ 和 DDT？

- λ 控制作业到达节奏，反映负载压力。
- DDT 控制交期紧度，反映交付压力。
- 动态组合可以模拟不同生产场景，比固定单一环境更适合观察策略适应性。

### Q4：为什么维护端要设计 hier DDQN？

- 维护决策包含两个问题：当前是否需要维护，以及如果维护应执行 IM 还是 CM。
- 单层 DDQN 把两个问题压缩在 DN/IM/CM 三个动作中，容易混淆维护时机和维护类型。
- hier DDQN 把两类判断拆开，更适合表达维护节奏。

### Q5：为什么不用端到端工序-机器匹配？

- 端到端动作空间会随作业数和机器数快速变大。
- rule-based 动作选择可以压缩动作空间，并保留调度规则的可解释性。
- 这是本阶段实现和实验分析的合理折中。
