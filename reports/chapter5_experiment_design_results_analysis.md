# 第五章 实验设计、结果与分析

## 5.1 实验目标与总体流程

本章对本文提出的“调度-维护协同优化”框架进行结果披露与横向比较。与前文侧重模型建模和算法实现不同，本章重点回答四个问题：

1. 本文如何构造 `PPO/THDQN × flat_ddqn/hier_ddqn/pomcp` 的 6 组配对实验。
2. 仿真系统中的机器、退化曲线、任务到达、加工时间和维护参数分别如何设置。
3. 正式实验中的 RUL 信号来自哪些退化数据，以及该信号如何注入调度-维护协同决策。
4. 六组策略在调度、维护和整体成本上的差异分别意味着什么。

本章实验流程可概括为：首先利用公开过滤器退化数据构建机器健康演化与 RUL 预测模块；随后在同一批到达场景和相同随机种子下，分别训练与评估 2 类调度器和 3 类维护器；最后从总成本、延期、维护行为、健康余量和策略结构等维度进行分析。

表5-1给出了本章实验中各模块的输入与输出定义。

| 模块 | 输入 | 输出 |
| --- | --- | --- |
| RUL 预测器（paper_gru） | 长度为 30 的 `Differential_pressure` 时序窗口 | 归一化 `RUL∈[0,1]` |
| PPO 调度器 | 15 维车间全局状态 | 6 选 1 调度规则 |
| THDQN 调度器 | 15 维全局状态、11 维低层状态 | 高层目标 `g∈{0,1,2,3}` 与低层规则 `r∈{0,...,5}` |
| flat_ddqn 维护器 | 18 维机台局部状态 | `DN / IM / CM` |
| hier_ddqn 维护器 | 20 维机台局部状态 | gate:`DN/MAINT` 与 type:`IM/CM` |
| pomcp 维护器 | 18 维观测状态与规划搜索树 | `DN / IM / CM` |

其中，6 条调度规则的含义如下：

- `rule 0`: EDD + earliest idle
- `rule 1`: EDD + SPT machine
- `rule 2`: max urgency*tardiness + SPT
- `rule 3`: SRPT + SPT
- `rule 4`: LRPT + earliest idle
- `rule 5`: min slack + earliest idle

对于 THDQN，高层目标的奖励定义如下：

- `goal 0`: 仅最小化延期增量
- `goal 1`: 仅最小化维护成本增量
- `goal 2`: 最小化 `tardiness + 0.3 * maintenance`
- `goal 3`: 最小化 `0.3 * tardiness + maintenance`

### 5.2.4 调度器-维护器配对设计

本章采用配对矩阵实验，即 2 种调度模型与 3 种维护模型两两组合，得到 6 组实验：

1. `PPO + flat_ddqn`
2. `PPO + hier_ddqn`
3. `PPO + pomcp`
4. `THDQN + flat_ddqn`
5. `THDQN + hier_ddqn`
6. `THDQN + pomcp`

其中：

- `PPO` 使用 `PPO_ENTROPY` 变体，并采用 `legacy_balanced` 奖励版本；
- `THDQN` 为层级式调度器，高层输出目标、低层输出规则；
- `flat_ddqn` 为单层 3 动作 DDQN；
- `hier_ddqn` 为门控/类型双层 DDQN；

从表5-5可以直接得到三个结论：

1. `hier_ddqn` 是本轮最稳定、最有效的维护结构。无论搭配 `THDQN` 还是 `PPO`，它都优于同调度器下的 `flat_ddqn`。
2. `THDQN` 的优势并不是普遍成立，而是依赖维护器结构。当维护器切换为 `hier_ddqn` 时，`THDQN` 明显优于 `PPO`；但搭配 `flat_ddqn` 或 `pomcp` 时，`PPO` 反而更稳。
3. 修正后的 `pomcp` 已经不再触发故障，但仍然存在“安全裕度较大、维护成本偏高”或“健康最小值偏低”的两种不同表现，说明其规划能力已恢复可用，但稳定性尚未超过 `hier_ddqn`。

### 5.3.2 PPO 组结果分析

#### （1）`PPO + flat_ddqn`

`PPO + flat_ddqn` 的总成本为 `206.609`，其中延期成本高达 `192.609`，而维护成本仅 `14.0`。其维护动作分布为：

- `DN = 268`
- `IM = 14`
- `CM = 0`

这说明单层 DDQN 在 PPO 调度器下明显偏向“不维护或轻维护”，从而几乎完全避免了 `CM`。从规则分布看，该组合主要集中在：

- `rule 1 = 115`
- `rule 5 = 115`

即大量依赖 `EDD + SPT machine` 与 `min slack + earliest idle` 两类规则。该策略的优点是维护开销极低，但缺点是延期明显偏高，说明仅靠平面规则选择和极少维护难以在 9 个 `λ-DDT` 组合下保持全局效率。

#### （2）`PPO + hier_ddqn`

`PPO + hier_ddqn` 的总成本下降到 `167.094`，比 `PPO + flat_ddqn` 降低了 `39.515`。这一改进主要来自延期成本显著下降：

- `Δtard = -61.515`
- `Δmaint = +22.000`

维护动作分布为：

- `DN = 261`
- `IM = 16`
- `CM = 4`

与 `flat_ddqn` 相比，`hier_ddqn` 开始在必要位置引入少量 `CM`，同时把末端健康均值提升到 `0.617`。其规则分布集中于：

- `rule 0 = 144`
- `rule 3 = 93`

即主要在 `EDD + earliest idle` 与 `SRPT + SPT` 之间切换。相比 `flat_ddqn`，该组合的规则集中度更高（`rule_top1_share = 0.5106`），说明 PPO 在配合分层维护器时，会倾向形成更稳定、更少切换的调度风格。

#### （3）`PPO + pomcp`

`PPO + pomcp` 的总成本为 `172.997`，略高于 `PPO + hier_ddqn`，但其延期成本更低，仅为 `114.997`。这意味着 `pomcp` 用更高的维护成本换来了更低的延期：

- 相比 `PPO + hier_ddqn`，`Δtard = -16.097`
- 但 `Δmaint = +22.000`

该组合的维护动作分布为：

- `DN = 258`
- `IM = 13`
- `CM = 9`

这说明修正后的 `pomcp` 已经能够主动触发 `CM`，而不是停留在“只做 IM”的早期失效状态。与此同时，它的末端健康均值最高（`0.741`），表明该策略显著增加了安全余量。但由于维护动作更积极，其整体总成本仍略逊于 `PPO + hier_ddqn`。

从规则分布看，该组合主要使用：

- `rule 1 = 116`
- `rule 5 = 60`
- `rule 0 = 57`
- `rule 2 = 49`

与 `PPO + hier_ddqn` 相比，`PPO + pomcp` 的规则更加分散，说明维护端的规划式干预会反向改变 PPO 在调度端的动作偏好。

### 5.3.3 THDQN 组结果分析

#### （1）`THDQN + flat_ddqn`

`THDQN + flat_ddqn` 是本轮最差组合，总成本达到 `439.669`，其中延期成本高达 `422.669`。虽然其维护成本只有 `17.0`，但这并不能视为优点，因为该组合实际上是以大量延期换来的“低维护”。

其维护动作分布为：

- `DN = 265`
- `IM = 17`
- `CM = 0`

高层目标分布为：

- `goal 1 = 132`
- `goal 0 = 67`
- `goal 3 = 53`
- `goal 2 = 30`

这表明 THDQN 的高层更频繁地激活“偏维护”目标，但维护器本身又没有足够的层级表达能力去实施更有效的 `CM/IM` 组合，结果导致“高层想保守，维护端做不到，延期端又失控”的结构失配。

#### （2）`THDQN + hier_ddqn`

`THDQN + hier_ddqn` 是本轮最佳组合，总成本仅 `113.170`，同时具备最低延期成本 `79.170` 和较高健康余量。其维护动作分布为：

- `DN = 264`
- `IM = 14`
- `CM = 4`

高层目标分布为：

- `goal 0 = 139`
- `goal 2 = 71`
- `goal 1 = 42`
- `goal 3 = 30`

低层规则分布为：

- `rule 5 = 87`
- `rule 2 = 86`
- `rule 3 = 56`
- `rule 4 = 27`
- `rule 1 = 26`

可以看出，这一组合并没有退化为单一规则，而是在 `rule 2`、`rule 5` 和 `rule 3` 之间形成了较为均衡的切换，`rule_top1_share = 0.3085` 也是六组中最低之一。这说明 THDQN 的层级目标确实在驱动低层规则做场景适配，而不是简单重复同一种规则。

按 `λ-DDT` 组合进一步观察，该策略在不同负载下会显著调整目标偏好：

- `lam=20, ddt=1.00`：以 `goal 3 + rule 2` 为主
- `lam=40, ddt=2.00`：以 `goal 2 + rule 5` 为主
- `lam=60, ddt=1.50`：`goal 0` 占比达到 `0.906`
- `lam=60, ddt=2.00`：以 `rule 5` 为主，兼顾延迟与健康

这说明 THDQN 的优势来自“高层目标切换 + 低层规则匹配”的协同，而这一点必须依赖 `hier_ddqn` 维护器提供足够稳定的健康控制。

根据表5-6，可以给出以下解释：

1. **`hier_ddqn` 是当前最优维护结构。**  
   它在 PPO 和 THDQN 两类调度器下都表现出稳定优势，说明“先判断是否维护、再判断维护类型”的层级结构更适合本文的健康-任务耦合场景。

2. **THDQN 并非天然优于 PPO。**  
   在 `flat_ddqn` 和 `pomcp` 下，PPO 的总成本都低于 THDQN；只有当维护器也具备层级表达能力时，THDQN 的高层目标切换优势才能被释放出来。

3. **修正后的 POMCP 已从“故障型策略”变成“安全型策略”。**  
   本轮 6 组实验全部无故障，说明 POMCP 路径上的安全约束修正是有效的；但 POMCP 在两种调度器下都不是最优，说明它目前仍偏向用更高维护换取更高健康安全余量。

4. **当前最有论文主结论价值的组合是 `THDQN + hier_ddqn`。**  
   它不仅取得了最低总成本与最低延期，而且其目标切换与规则切换具有清晰的解释性，因此最适合作为本文主模型的结果展示对象。

## 5.4 本章小结

本章围绕 6 组“调度器-维护器”配对实验，对实验设计、数据来源、参数设置与结果表现进行了系统披露。实验结果表明：

- 在统一的 `81` 作业、`9` 个 `λ-DDT` 组合和单种子配对条件下，`THDQN + hier_ddqn` 取得了最佳综合性能；
- `hier_ddqn` 是当前最稳健的维护结构，而 `flat_ddqn` 更像低维护成本但高延期风险的基线；
- 修正后的 `pomcp` 已经能够避免故障，但仍存在维护偏重或健康余量利用不足的问题；
- RUL 预测器在本轮实验中作为内部健康信号提供器使用，其输入来源与机台映射关系已经在本章中完成披露，并为后续调度-维护联动提供归一化 RUL 状态输入。

因此，若以论文主实验的结果表达为目标，本章建议以 `THDQN + hier_ddqn` 作为主模型，将 `PPO + hier_ddqn`、`PPO + pomcp` 作为横向对比组，将 `flat_ddqn` 两组作为基线组，用以突出层级维护结构和层级调度结构的协同收益。
